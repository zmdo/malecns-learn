00这一阶段要做什么What Phase 1 is

阶段 0 给了你词汇，阶段 1 让你用词汇换取真实结构。 具体说：打开连接组数据库，从已知的一个神经元出发， 沿着连接一路走到另一个已知神经元，并说出中间每一个细胞类型。

✅ 为什么这个练习这么重要

「走通一条通路」是连接组学所有后续工作的最小完整闭环： 你要会按类型查神经元（不是按 ID）、会看上下游连接、 会判断哪条边值得信任（权重够不够）、会用形态和解剖位置交叉验证。 这四件事在阶段 3 写代码时是同一件事，只是换成了 API。

指南原文可检查的动作

02neuPrint 实操The main tool

neuPrint 是 MaleCNS 的官方门户。它背后是一个 Neo4j 图数据库 —— 神经元是节点，连接是边。网页界面是它的外壳，而它同时开放了一个 只读匿名 API，这正是本页所有数字的来源。

✅ 好消息：匿名也能查，不用注册

我实测过 neuprint.janelia.org：不需要 token 就能跑查询 （走的是共享的只读账号）。这对学习阶段完全够用。真要批量拉数据时再申请个人 token。

🖥 不想手打查询？用配套的执行台

这一节的查询我做成了一个可以直接跑的网页： neuPrint 查询执行台 →

里面有 22 条预设查询（就是下面 §05 / §06 里那些）， 点一下填入编辑器、按 Ctrl+Enter 就能从 neuPrint 取回真实数据， 结果支持点表头排序、并可直接导出 CSV。 它直接从你的浏览器调用官方 API（该端点开放 CORS）， 不需要 token，也不需要本地后端 —— 打开就能用（需联网）。

查询语言：Cypher，但只需要会四句式

neuPrint 用的是 Neo4j 的 Cypher。你不需要学它 —— 阶段 1 只要会下面四种模式，就能走通任何通路。

// 句式一：按类型找神经元（拿到 bodyId） MATCH (n:Neuron) WHERE n.type = 'DNg13' RETURN n.bodyId, n.instance, n.superclass, n.consensusNt // 句式二：看某个神经元的上游（谁连到它） MATCH (m:Neuron)-[r:ConnectsTo]->(n:Neuron {bodyId: 11074}) RETURN m.type, m.bodyId, r.weight ORDER BY r.weight DESC LIMIT 25 // 句式三：看某个类型的下游（它连到谁） MATCH (a:Neuron {type: 'R1-R6'})-[r:ConnectsTo]->(b:Neuron) RETURN b.type, b.superclass, count(*) AS n, sum(r.weight) AS w ORDER BY w DESC LIMIT 20 // 句式四：按超类汇总输出（判断它主要连去哪一区） MATCH (n:Neuron {bodyId: 11074})-[r:ConnectsTo]->(m:Neuron) RETURN m.superclass, count(DISTINCT m) AS targets, sum(r.weight) AS total ORDER BY total DESC

句式四是本页用得最多的一招：当你想知道"这个神经元把信息送到哪个脑区"时， 按 superclass 汇总比逐条看目标类型快得多 —— 一眼就能看出它偏向 vnc_*（下行）、cb_*（中央脑）还是 ol_*（视叶）。

⚠️ 两个必须记住的字段名陷阱
  • 细胞类型字段叫 type，不是 cellType。 写错不会报错，只会返回 0 行 —— 这个坑我踩过。
  • 连接关系的类型叫 ConnectsTo（还有 Contains、 SynapsesTo）。upstream/downstream 只是神经元上的计数属性，不是可查询的关系。

查询方向怎么定？看 pre / post 就知道

最容易搞错的是边的方向。判据很简单：先查目标神经元的 pre（突触前位点） 和 post（突触后位点）。pre 多的偏输出，post 多的偏输入。 以 DNg13 为例：

DNg13_L (bodyId 11074): pre = 2,127 post = 6,500 # post 远多于 pre → 偏输入型 # 但真正要看的是「它输出到哪」——下行神经元必须输出到 VNC： MATCH (n:Neuron {bodyId:11074})-[r:ConnectsTo]->(m:Neuron) RETURN m.type, r.weight ORDER BY r.weight DESC LIMIT 5 # 结果里出现 Tergopleural/Pleural promotor MN（运动神经元） # → 证实这个方向是从脑到 VNC 的「下行」输出，方向找对了

这就是"用生物学常识校验查询方向"： 如果你以为的"输入"里冒出运动神经元，那说明方向反了，把箭头掉个头。

匿名 API：同样四句式，可脚本化

网页界面点起来直观，但真正方便的是它背后那个端点。同一套 Cypher， 一个 HTTP POST 就能拿到 JSON —— 这也是阶段 3 写代码时的入口。 

# 任意 shell 都能跑；不需要 token
Q="MATCH (n:Neuron) WHERE n.type = 'DNg13' RETURN n.bodyId, n.consensusNt"

curl -s -X POST 'https://neuprint.janelia.org/api/custom/custom' \
  -H 'Content-Type: application/json' \
  -d "{\"cypher\": \"$Q\", \"dataset\": \"male-cns:v1.0\"}"

用 Python 更顺手（标准库就够，不用装 neuprint-python）：

import json, urllib.request

BASE = "https://neuprint.janelia.org"
DS   = "male-cns:v1.0"

def cypher(q):
    req = urllib.request.Request(
        BASE + "/api/custom/custom",
        data=json.dumps({"cypher": q, "dataset": DS}).encode(),
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=120) as r:
        return json.loads(r.read().decode())

# 走通通路 A 的第一跳
d = cypher("""MATCH (a:Neuron {type:'R1-R6'})-[r:ConnectsTo]->(b:Neuron)
               RETURN b.type, b.superclass, count(*) AS n, sum(r.weight) AS w
               ORDER BY w DESC LIMIT 5""")
for row in d["data"]:
    print(row)

03Codex 实操Cross-check on another dataset

Codex 是 FlyWire 的界面，但它把 5 个数据集放在同一个搜索框后面： FAFB（雌性脑）、BANC（雌性脑+索）、MANC（雄索）、MAOL（雄右视叶）、 MCNS（就是 MaleCNS）。

🧭 阶段 1 用 Codex 只做三件事
  1. 看看雌性脑里同一条通路长什么样 —— 通路 A 的细胞类型在 FAFB 上基本都能找到， 对比一下连接权重，你会直观感受到「性别与范围的差异」。
  2. 用 @ 跨库搜类型：搜索框里输入 @ T4a， 会在所有数据集里搜 T4a，一次看全。
  3. 用图形化的 Path Length App 手工点路径 —— 比写 Cypher 门槛低， 适合先建立直觉（下节详述）。

Codex 的 Path Length App：不写查询也能找路

neuPrint 要你写 Cypher，Codex 则提供了一个纯图形化的找路工具： codex.flywire.ai/app/path_length （官方说明见 Finding Paths in Codex）。

控件说明
Source cells起点，最多 10 个。可以直接填 body ID，也可以用搜索框按类型找
Target cells终点，同样最多 10 个
Synapse threshold每条连接的最低突触数，默认 5（与 neuPrint 的 MCNS 默认口径一致，可调高）
Grouping结果的分组方式（下拉选择）
结果视图默认是**矩阵视图**，给出每对 source/target 的最短路径长度 （= 最少需要几"跳"）。点 View Pathways Chart 切成交互式路径图： 边的**颜色按递质编码、宽度反映连接强度**，悬停节点会弹出细胞信息卡片
✅ 为什么值得用一下这个工具

它回答的是一个 neuPrint 不容易直接回答的问题： 「从 A 到 B 最少要几跳？」 比如把 source 设成 R1-R6、target 设成 DNg13， 看矩阵里的最短跳数 —— 你会发现它比你想的短， 这本身就是对「小世界网络」的直观感受。 然后用 Pathways Chart 把那条最短路径展开，逐节点核对。

⚠️ 别指望在 Codex 里下载数据

Codex 对 MCNS 只做交互式浏览，不做权威下载； 部分交互应用需要 Google 登录，静态页面免登录。 要原始数据请走官方下载页（阶段 3 的事）。

04Cell Type ExplorerDoes this type exist?

Cell Type Explorer 是 MaleCNS 的类型总目录加一张类型→类型连接矩阵。 它的定位很明确：回答"有没有、叫什么"，而不是"连多少"。

它提供怎么用
细胞类型目录 按名字或按脑区浏览全部类型。通路 A 里出现的 T4、T5、 L1、Tm2 都能在这里找到，看到它们各有多少个实例
类型→类型连接矩阵 矩阵的行是输入、列是输出（或反之，界面会标）。 格子里的数字是该类型对之间的突触总数 —— 相当于把 neuPrint 的逐细胞查询按类型聚合了一次
eyemap 视叶细胞的「眼图」排布，用来快速判断一个视觉细胞的类型与所在层
✅ 推荐的工作流

先在 Cell Type Explorer 确认类型存在 → 再到 neuPrint 查它的具体连接 → 再用 Codex 在另一个数据集上复核。 先用目录筛掉不存在的名字，能省掉大量在 neuPrint 里查空结果的时间。

逐跳复现：七个查询走完全程

下面每个查询都可以直接粘进 neuPrint 的查询框（或上面的 Python 函数）。 建议一边跑一边把结果记下来 —— 那张记录就是阶段 3 的对照答案。

1先确认起点存在：R1–R6 是什么
MATCH (n:Neuron {type:'R1-R6'})
RETURN n.bodyId, n.instance, n.superclass, count(*) AS c
ORDER BY n.bodyId LIMIT 5

你会看到一批 ol_sensory 的细胞 —— 这就是复眼里的外层光感受器。注意 type 里写的就是 R1-R6， 六种光感受器在 MaleCNS 里被合并成一个类型。

2第一跳：光感受器投向谁
MATCH (a:Neuron {type:'R1-R6'})-[r:ConnectsTo]->(b:Neuron)
RETURN b.type, b.superclass, count(*) AS n, sum(r.weight) AS w
ORDER BY w DESC LIMIT 8

排在前面的应该是 L2、L1、L3（都是 ol_intrinsic）， 权重在十万量级。这就是板层单极细胞，也是链条的第一环。

3第二跳：L1/L2 往下传给谁
MATCH (a:Neuron {type:'L2'})-[r:ConnectsTo]->(b:Neuron)
RETURN b.type, b.superclass, count(*) AS n, sum(r.weight) AS w
ORDER BY w DESC LIMIT 8

结果里出现 Tm2、Tm1、Tm4（权重各二十万上下）。 这些是髓质里的跨髓质细胞，运动通路的第一批"计算单元"。

4第三跳：找到方向选择细胞 T4/T5
MATCH (a:Neuron)-[r:ConnectsTo]->(b:Neuron)
WHERE a.type IN ['Tm1','Tm2','Tm4'] AND b.type STARTS WITH 'T'
RETURN a.type AS 上游, b.type AS 下游, sum(r.weight) AS w
ORDER BY w DESC LIMIT 10

会看到 Tm2 → T5a/b/c/d、Tm1 → T3 等。 T4 和 T5 是果蝇视觉里最著名的方向选择细胞： T4 管亮边、T5 管暗边，各自只对四个方向之一响应。

5第四跳：方向选择细胞往下传给谁
MATCH (a:Neuron)-[r:ConnectsTo]->(b:Neuron)
WHERE a.type STARTS WITH 'T4' OR a.type STARTS WITH 'T5'
RETURN a.type AS 上游, b.type AS 下游, b.superclass AS sc, sum(r.weight) AS w
ORDER BY w DESC LIMIT 10

出现 LPi34、LPi21、Tlp14、VS —— 这些是小叶板的切向细胞（LPTC）， 负责把局部运动信号汇集成"整体光流"。VS 已经属于 visual_projection，意味着它准备离开视叶进入中央脑。

6终点：找到 DNg13，看清它的身份
MATCH (n:Neuron) WHERE n.type = 'DNg13'
RETURN n.bodyId, n.instance, n.superclass, n.consensusNt,
       n.flywireType, n.pre, n.post

返回两行：DNg13_L（bodyId 11074）与 DNg13_R（512006）。pre 远小于 post， 符合"输入型"的形态；consensusNt 是 acetylcholine。

7确认它真的是下行神经元：输出到 VNC 运动神经元
// 先看输出的超类分布：应该以 vnc_* 为主
MATCH (n:Neuron {bodyId:11074})-[r:ConnectsTo]->(m:Neuron)
RETURN m.superclass, count(*) AS 目标数, sum(r.weight) AS 总权重
ORDER BY 总权重 DESC

// 再单独把运动神经元挑出来
MATCH (n:Neuron {bodyId:11074})-[r:ConnectsTo]->(m:Neuron)
WHERE m.superclass = 'vnc_motor'
RETURN m.type, m.instance, r.weight ORDER BY r.weight DESC LIMIT 6

第一条查询的输出里，vnc_intrinsic（373 个目标）和 vnc_motor（17 个目标）占了绝对多数 —— 这就是"脑 → VNC"方向的铁证。

第二条查询给出具体的运动神经元： Tergopleural/Pleural promotor MN（w=60）最强， 后面还有 Sternal posterior rotator MN、Pleural remotor/abductor MN 等 —— 都是控制足与翅基部运动的肌肉。 整条通路到此闭合：光子 → 视觉计算 → 下行指令 → 动腿。

🔍 顺手发现的一件有意思的事

DNg13 的输出里还有 35 个 ascending_neuron（上行神经元） 和 42 个别的 descending_neuron。 训练有素的读者会立刻意识到：下行神经元并不是单向的管道末梢， 它们参与本地网络、也会向上升神经元反馈。 这类"非教科书式"的连接正是连接组数据的价值所在 —— 阶段 3 算完度分布后，你可以回来验证这个观察。

06通路 B · 糖味觉 → 摄食Sugar GRN → SEZ → MN9

如果通路 A 太长，先走这条。它只有 3 跳， 而且是 Shiu et al. 2024 用来验证全脑模型的标准实验（糖刺激 → 喙伸出反射）。

🎯 结论：这条链在 MaleCNS 里找得到

糖味觉 → 摄食，实测链条：

#细胞类型层级 / 说明权重
起点BM_Taste糖味觉感觉神经元 · cb_sensory，投射到颚神经毡—
1GNG015 / GNG178颚神经毡局部中间神经元 · cb_intrinsic1,376
2GNG654感觉中继（可直达 MN9）· cb_sensory153
终点MN9喙肌运动神经元 · cb_motor（MN9_L / MN9_R）—

关键在于缩写对应关系：Shiu 2024 说的「SEZ」（食管下区）， 在 MaleCNS 的 type 字段里写成 GNG（颚神经毡）。 不知道这个对应，你会在 neuPrint 里搜 SEZ 搜不到东西。

1找到 MN9
MATCH (n:Neuron) WHERE n.type = 'MN9'
RETURN n.bodyId, n.instance, n.superclass

返回 MN9_L（10331）与 MN9_R（16949），超类 cb_motor。

2看谁在驱动 MN9
MATCH (a:Neuron)-[r:ConnectsTo]->(b:Neuron {type:'MN9'})
RETURN a.type, a.superclass, sum(r.weight) AS w
ORDER BY w DESC LIMIT 12

大量 GNG* 出现（GNG015、GNG120、GNG095…）， 还有 DNge062 这样的下行神经元。 到这里你就把「SEZ」在数据里定位出来了。

3往上追：谁给 GNG 供输入
MATCH (a:Neuron)-[r:ConnectsTo]->(b:Neuron {type:'GNG015'})
RETURN a.type, a.superclass, sum(r.weight) AS w
ORDER BY w DESC LIMIT 12

最强的输入是 BM_Taste（cb_sensory）—— 这就是糖味觉感觉神经元。链条闭合了。

✅ 起点身份：为什么可以确定 BM_Taste 就是糖味觉输入

三条证据叠起来：

  • MaleCNS 里恰好只有一个味觉感觉类型。 全库搜 type CONTAINS 'Taste' 只返回 BM_Taste 一个类型 （40 个实例，cb_sensory）。其余 BM_* 都是机械感觉 （BM_InOm 本体感觉、BM_Vib 振动、BM_Hau 钩状感觉…）。
  • 它的下游结构分布完全吻合：94% 的权重落在 cb_intrinsic（327 个目标，权重 22,063，即食管下区局部网络） 与 descending_neuron（132 个目标，权重 13,078）。 一个感觉神经元把绝大部分输出投给摄食中枢 —— 这正是味觉 GRN 的行为。
  • 与 Shiu 2024 的补充表可以对照：该文补充表 2/3/4 列出了 21 个名为 sugar_l_1…sugar_l_20 的 FlyWire 神经元 ID （例如 720575940611875570 = sugar_l_20）， 以及喙肌运动神经元 MN9_r / MN9_l。

但要划清界限：那两个数据集用各自的 ID 体系（FlyWire FAFB 是雌性脑）， 而且 Shiu 的「sugar」标注来自他们的功能性钙成像实验， 不等于 MaleCNS 的注释类型名。 所以正确的说法是「BM_Taste 是 MaleCNS 中唯一对应的味觉感觉类型」， 而不是「BM_Taste 就是 Shiu 刺激的那 21 个细胞」。

🔎 一个顺手捡到的一致性检查

Shiu 2024 补充表里的喙肌运动神经元叫 MN9_r / MN9_l（小写）， MaleCNS 里叫 MN9_R / MN9_L（大写）。 类型命名一致、大小写习惯不同 —— 这种细节在阶段 3 做跨数据集匹配时会咬人。 写匹配脚本时记得做大小写归一化。

⚠️ 必须一起声明的前提
  • Shiu et al. 2024 用的是 FlyWire FAFB（雌性、仅脑）， 不是 MaleCNS。这条链在 MaleCNS 上能对上， 但不等于"同一个实验在雄性上做过"。
  • 2026-09 另有一篇味觉连接组 Cell 论文 （DOI 10.1016/j.cell.2026.08.016）， 在 MaleCNS + MANC + FAFB 上重算了 GRN–MN 有效连接。 引用"最新证据"时应并引。
  • 我给出的 GNG015 / GNG654 是中继链里的 在数据里权重最高的候选，不是论文钦定的那一条。 若要严格对应会引发 MN9 放电的那条通路，需要用阶段 4 的模型做有效连接分析。

08网页里最容易踩的坑Tool-level pitfalls

1 · 字段名是 type，不是 cellType

写成 cellType 不会报错，只会返回 0 行， 很容易误判成"这个类型不存在"。同理连接关系是 ConnectsTo， 而 upstream/downstream 只是计数属性，不能当关系查。

2 · 边方向搞反

Cypher 里 (a)-[:ConnectsTo]->(b) 是 a 输出给 b。方向反了会得到"光感受器接收运动神经元输入"这种荒谬结果， 而且不报错。用生物学常识兜底：下行神经元的输出必须是 VNC。

3 · 拿不同口径的数字互相比较

neuPrint / Codex 的 MCNS 默认 ≥5 突触才计一条连接； 下载的 flat connectome 用 min confidence 0.5。 两套口径下同一个类型对的数字会差很多。先问口径，再比大小。

4 · 把「类型」当「实例」

DNg13 是类型， DNg13_L 才是实例，两者各有自己的 bodyId。 按类型查会返回多行；按 bodyId 查才能定位到左右具体哪一个。 写代码做统计时，分组键选错了会全盘出错。

5 · 直接搜「SEZ」搜不到东西

MaleCNS 的 type 用 GNG 表示食管下区/颚神经毡。文献缩写 ≠ 数据集里的类型前缀 —— 遇到搜不到的名字，先去 Cell Type Explorer 看官方拼法。

6 · 以为网页上看到的权重就是"连接强度"

权重是突触计数，不是电流也不是概率。 而且它没有归一化 —— 一个 post 有 6500 个突触的神经元， 和 post 只有 50 个的神经元，收到同样 27 个突触的生物学含义完全不同。 比较权重前先看该细胞的 total post。

点方框看答案。全部能不看答案说出，就进阶段 2。

✓
阶段 1 的过关标准原文是什么？
「能走通 R1–R6 → … → DNg13 或 糖 GRN → SEZ → MN9，并说出中间细胞类型。」
✓
视觉通路中间那串"…"至少包含哪四组细胞？
① L1 / L2（板层单极细胞） ② Tm1 / Tm2 / Tm4（髓质内在神经元） ③ T4 / T5（方向选择细胞） ④ LPi34 / VS 等 LPTC（小叶板切向细胞）， 之后经视觉投射神经元进入侧副叶，接到 DNg13。
✓
三个工具各自的定位是什么？
Cell Type Explorer 回答"有没有这个类型、官方拼法是什么"； neuPrint 回答"它连谁、连多少"（MaleCNS 权威连接）； Codex 用来跨数据集复核（尤其换到雌性脑 FAFB 做对照）。
✓
怎么判断一条边是"输入"还是"输出"？
两个办法：① 看 Cypher 里的箭头方向 —— (a)-[:ConnectsTo]->(b) 表示 a → b； ② 用 pre/post 计数与生物学常识交叉验证。 最重要的兜底：下行神经元的输出里必须有 VNC 目标。
✓
为什么通路 A 最后几跳权重骤降到几十，这是数据问题吗？
不是。视叶是高度汇聚的结构（一个 L2 接收十万级突触）， 而中央脑局部环路规模小得多。权重只能在同区域同量级内比较； 跨区域比绝对值会得出错误结论。
✓
「SEZ」在 MaleCNS 数据里叫什么？
GNG（颚神经毡 / gnathal ganglion）。 文献缩写与数据集类型前缀常常不一致，搜不到时先去 Cell Type Explorer 查官方拼法。
✓
Shiu 2024 的糖 → MN9 实验用的是哪个数据集？
FlyWire FAFB（雌性、仅脑），不是 MaleCNS。 它是计算模型论文。引用时务必限定数据集，否则会被误读成"MaleCNS 上做过这个实验"。
✓
这一阶段做完，你应该留下什么产物？
