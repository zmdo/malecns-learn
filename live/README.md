# 左蝇右脑 · MaleCNS 实时闭环演示

一个**本地服务 + 网页**的实时闭环：
**左边**是解剖级蝇体在 MuJoCo 里真的走路，**右边**是 MaleCNS 的脑区 3D 视图。
**点右边任意脑区 → 往那组神经元注入电流 → 左边蝇子的运动当场改变。**

一切都在**本机**跑：不是录像，不是服务端串流。

```
live/
  regions.py     脑区/细胞类型 → 图索引 的映射（数据驱动，无写死列表）
  server.py      仿真线程 + HTTP/MJPEG 服务（只用标准库）
  web/index.html 左蝇右脑的界面
  web/app.js     MJPEG 接收 + 3D 脑 + 点击刺激
```

## 跑起来

需要 fly-arena 的环境（`_ref/.venv-arena`，Python 3.12 + flygym + MuJoCo）
和它编译好的图（`_ref/arena-data/graph/`，见主 README 的「蝇体 + 大脑具身演示」一节）。

```bash
MPLCONFIGDIR=/tmp/mpl MUJOCO_GL=cgl \
  _ref/.venv-arena/bin/python live/server.py --port 8099
# → http://127.0.0.1:8099
```

> `MUJOCO_GL=cgl` 在 macOS 上走离屏渲染，**不需要图形界面**。

## 界面

- **左**：MuJoCo 实时画面，相机跟随蝇子（俯角 -52° 的 3/4 视角）。实测 ~34 fps。
  传输方式是 **canvas + 长轮询 `/frame?since=N`**，不是 `multipart/x-mixed-replace`：
  Safari 对 `<img>` 里的 MJPEG 支持不稳定，会出现「什么都不显示」；
  长轮询则任何浏览器都一样，而且服务端只在有新帧时才回，不会空转狂拉。
- **右**：MaleCNS 的 26 个神经毡网格，可拖动旋转、滚轮缩放。
  每个脑区中心有一个**发光点，大小与颜色随该组实时放电率变化** —— 这就是「展示放电的神经元」。
- **下**：30 个可刺激组，按具名行为神经元优先、其余按规模排序，每条带实时放电率与进度条。
  点条目或点 3D 脑区都能刺激。
- 刺激强度 1–30 mV、时长 50–2000 ms 可调。

## 实测：刺激真的改变运动

在本机跑的三段对照（速度已投影到蝇子当时的头朝向，正=向前）：

| 阶段 | 沿头朝向速度 | 说明 |
|---|---|---|
| ① 基线（无刺激） | **1.63 mm/s** | |
| ② **MDN** 25 mV | **0.05 mm/s** | 倒退指令 → 前进被抑制 |
| ③ 基线（对照） | 1.66 mm/s | |
| ④ **DNp09** 25 mV | **5.02 mm/s** | 前进指令 → 约 **3×** 加速 |
| ⑤ 基线（对照） | 1.54 mm/s | |
| ⑥ **DNp01** 25 mV | 1.55 mm/s | 巨纤维（逃跑）—— **本组没有观察到起飞**，见下 |

- 每段刺激之间都插了基线，避免把漂移当成效果。
- `DNp01` 是逃跑命令神经元，预期是起飞而不是加速；这次没看到高度变化，
  说明在 fly-arena 的这套接口下它还依赖别的门控。**如实记录，不当成有效果。**

整机性能：**0.30–0.31 × 实时**（单步 10 ms 仿真的墙钟约 28–34 ms，
其中大脑约 12 ms、物理 1.5 ms、渲染+JPEG 约 11 ms）。

## 四处刻意的工程改动（都写在代码注释里）

1. **地面必须在构造 Arena 之前放大**。MuJoCo 的 `PLANE` 碰撞是无限的，但
   **可见范围在编译期就固定成 `size=(half_size, half_size, 1)`** ——
   之后再改 `model.geom_size` **完全无效**（试过）。
   fly-arena 传的是 `half_size=22`（44×44 mm），蝇子一走出去地面就整个不渲染，
   画面只剩白底加一只浮空的蝇子。解法是在 `Arena(...)` 之前把
   `fly_arena.arena.FlatGroundWorld` 换成强制 `half_size=500` 的包装，用完还原。
   同时把 `mat_texrepeat` 从 14 重算成 `2*500/3.14`，保持棋盘格大小不变。
2. **装饰几何往外挪 + 从渲染里关掉**。边界墙 / 条纹 / 信标的位置按 4 倍外移
   （`geom_pos` 是运行时值，改了有效）。它们也全部进了 geom group 3 并被
   `scene_option.geomgroup` 关掉，原因有两个：
   - 条纹是纯装饰，rgba `[0.77 0.72 0.45]` 的橄榄绿 —— 相机一贴近就是
     **一条横穿全屏的绿色长条**（这就是你看到的那个 bug）；
   - `invisible_lid`（z=6.5，防蝇子飞走，rgba 透明）在相机抬高后会被穿过去，画面上一大块白。
3. **边界墙还会挡人**。flygym 把墙也塞进了 `world.ground_geoms`，于是给蝇腿和墙
   生成了**显式 contact pair** —— 即使 `contype/conaffinity` 都是 0 也照样挡。
   原版 fly-arena 跑 7 秒就停在 `(19.35, 18.0)` 不动，就是这个原因（A/B 验证过）。
4. **回中心**：① 离场地中心超过 **55 mm**；② 连续 4 生物秒位移速度低于 0.15 mm/s。
   两条都是**演示便利，不是蝇的行为**，页面上会显示回中心次数。

## 边界（哪些是测量、哪些是工程假设）

- ✅ **接线是测量**：166,700 个神经元、25,582,938 条有向边、突触数，全部来自官方 v1.0 文件。
- ⚠️ **LIF 参数、递质符号、步态程序、下行解码、运动神经元→关节的映射都是工程选择**。
- ⚠️ 脑区 → 神经元的分组是**按注释的 `type` / `superclass` 规则**划的（前缀匹配），
  不是按神经毡内实际树突分支；每个组的神经元数都从数据里数出来，可在 `/groups` 核查。

所以：这是「用真实连接组驱动的具身仿真」，**不是果蝇数字孪生**。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 界面 |
| GET | `/stream` | MJPEG 实时帧 |
| GET | `/state` | 遥测 + 每个组的实时放电率 |
| GET | `/groups` | 可刺激组目录（含神经元数与关联神经毡） |
| POST | `/stimulate` | `{"group":"DNp09","mv":20,"ms":1500}`；或 `{"action":"clear"}` / `{"action":"recenter"}` |
